Arcantry can describe an empty directory or an established project without creating files. Choose an installation path, inspect the project, then decide which sources Arcantry should only read and which it should manage.

## Resume work in three commands

```sh
arcantry context
arcantry next
arcantry explain tasks
```

`context` finds your sources and active work. `next` recommends an unblocked task; use `--change` to select one. `explain` supplies the format, example and project sources. Add `--json` for integrations or `--detailed` for the complete context and rules. These commands do not change files or infer approval from earlier conversations.

## Work without the CLI

Read `AGENTS.md`, the selected `arcantry.toml` (private configuration takes precedence), and `openspec/config.yaml`. Open the chosen change's `proposal.md` and `tasks.md`, then its selected schema template under `openspec/schemas/`. Follow the first unfinished task after its dependencies, using the current request as authority. Read only relevant private files, and keep them private. Edit ordinary source files directly and use the project's existing checks. Neither CLI installation nor a release is required for that work.

## Install Arcantry

Run Arcantry once with `npx`, install it with `npm` or a native installer, or download it from the official GitHub Release:

<ArcantryCommandPicker idPrefix="getting-started-install" />

- `npx` downloads Arcantry for one command without keeping a global installation.
- `npm` installs the `arcantry` command globally.
- PowerShell and `sh` install the native CLI from the matching GitHub Release and verify its SHA-256 checksum.
- `Download` opens the versioned GitHub Release for direct archive downloads.

Native downloads support Windows x64, macOS x64 and ARM64, and Linux x64.

## Inspect a project

After a persistent installation, inspect the current directory:

```sh
arcantry repo inspect
```

`arcantry repo inspect` is read-only: it does not create `arcantry.toml`, initialize Git, or modify a recognized source.

Use `--cwd` to inspect another directory:

```sh
arcantry --cwd ../project repo inspect
```

Add `--detailed` to expand adapter, management, methodology, and `.local` evidence. Add `--json` when another tool needs the complete versioned machine-readable result.

## Read the result

Inspection reports:

- the resolved project root and whether configuration was found;
- discovered or configured OpenSpec, changelog, and todo.txt sources;
- each source's path, visibility, management level, adapter, and compatibility;
- missing sources as valid absence rather than an initialization error.
- applicable agent guidance, Agent Skills, and project-work methodologies;
- whether `.local` is absent, protected, unprotected, or tracked by Git.

An empty result is valid. Git and `arcantry.toml` are not prerequisites.

## Choose what happens next

- Keep using configuration-free inspection when you only need a trace-free observer.
- Run `arcantry repo init --scope private` for untracked project context and private agent guidance.
- Run `arcantry repo init --scope shared` when collaborators need the same configuration and guidance.
- Use an explicit external `arcantry.toml` when the target project must remain unchanged.
- Use [todo.txt queues](/guides/todo-txt/) or [skills](/skills/) independently.
- Follow [Adoption paths](/adoption/) before planning a source transition.
- Use [Inspect, plan and apply](/reference/repository-workflow/) when a source must change.
