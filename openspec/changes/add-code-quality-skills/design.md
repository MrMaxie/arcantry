# Design

## Phase boundaries

The three skills form a deliberate sequence but remain independently routable. Assessment is read-only and produces prioritized findings with evidence, consequence and proportionate response. Design converts an accepted problem into explicit structural decisions without editing code. Refactoring requires implementation authorization and advances through verified behavior-preserving increments.

`stage-code-review-findings` continues to own approval-gated publication of review feedback. `verify-work-proportionally` continues to own selection of verification depth. The new skills may hand off to those workflows without duplicating their procedures.

## Evidence model

Refactoring.Guru supplies a vocabulary for smells, patterns and small-step refactoring. A candidate is not justified by that vocabulary alone. The agent inventories the affected code, reads project conventions and official language or framework guidance, and establishes a concrete maintenance or correctness cost. Functional, procedural, data-oriented and object-oriented designs remain equally valid when supported by the project.

## Evaluation

Each new package receives direct, indirect, negative and behavior cases. Negative cases protect the boundaries between review, design and implementation. At least three cases remain held out from drafting, and candidates are evaluated outside every live skill root before catalog adoption.
