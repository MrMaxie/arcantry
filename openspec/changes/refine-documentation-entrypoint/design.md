# Approach

Keep the changes inside the existing Astro and Starlight component overrides. The released version belongs under the header brand; authorship and repository ownership belong in the footer. The overview command picker uses equivalent public npm, pnpm, and Nub package-runner commands, stores only the selected runner name in local storage, and keeps the command row itself as the copy target. A narrow command decorator recognizes only public Arcantry CLI invocations outside existing buttons and code blocks, then adds keyboard-operable copy behavior without turning filenames or ordinary inline code into controls.

Use the canonical full wordmark on desktop instead of composing a separately scaled mark and cropped wordmark. Define semantic blue, violet, and pink accent tokens for both themes. Use them for syntax, selection, focus, navigation state, section structure, and a lightweight overview-only canvas atmosphere. The overview header keeps search near the brand at a compact desktop width, while documentation routes let it expand with the full shell. The header and command picker use only enough transparency and backdrop blur to separate overlapping content; the command surface remains dark enough to preserve syntax contrast over the saturated canvas.

Keep the atmosphere inside the existing Astro component stack. Use a soft procedural mist, independently drifting motes that fade fully between varied brightness peaks, and a dense but restrained field of angled falling stars inspired by the Arcantry identity rather than rendering the product mark, hard paths, or a technical diagram. The atmosphere spans the viewport while hero copy remains aligned to the centered content column, and its canvas uses responsive CSS dimensions so a resize or transition cannot expose a hard edge. Pointer light exists only during active hero interaction and clears on exit, scroll, or window blur. The canvas pauses outside the viewport, caps device-pixel density, fades at the hero edges, and renders a static frame when reduced motion is requested. The information-boundary navigation uses slower CSS gradient drift behind stable content. Use Astro's built-in `ClientRouter` for site-wide view transitions, keep the header horizontal, animate its inner width from the centered overview column to the full documentation shell, and crossfade changing page content without geometrically distorting it. Position fixed documentation dividers below the header so transition snapshots cannot paint them over the shell. Preserve the standard overview pager shape and add only an animated blue-violet-pink gradient border; keep a shared transition identity so it resolves into the standard documentation pager after navigation. Directional comparison rows use one connected SVG line-and-arrow path, avoiding a visually detached bar and arrowhead.

Order overview content by the public reader's decision path: concise hero, concrete value, manual-versus-Arcantry comparison, navigable product areas, setup, then expected repository outcomes. Present comparison as directional before-and-after rows and use an asymmetric result composition to separate the primary adoption guarantee from supporting outcomes. Use Fraunces as the single serif family and reserve the blue-violet-pink gradient for short emphasis rather than body copy.

# Trade-offs

The package-runner selector is overview-only. Reference and adoption pages continue to show the installed `arcantry` binary directly because those examples document CLI behavior rather than package execution.

The animated canvas is also overview-only. Documentation and reference pages receive the shared color and navigation-transition language without a decorative rendering layer, preserving reading performance and information density.
