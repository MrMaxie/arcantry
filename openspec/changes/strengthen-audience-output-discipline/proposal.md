# Why

Audience guidance can still turn requirements and available implementation data into reader-facing copy without first proving that the intended reader has a current task for that information. This produces generic explanations, internal metadata and invented fallback content even when the source and audience already establish a narrower result.

# What changes

- Require the skill to identify the primary audience, their current task, existing knowledge and established terminology before editing.
- Treat enumerated requirements and available fields as implementation inputs unless the request, audience contract or current task admits them into the artifact.
- Preserve exact technical values when an established verification or support task requires them.
- Add a focused requirement-to-result reference that demonstrates the decision without becoming a field blacklist or reusable copy template.
- Reflect the decision boundary in generated public skill documentation through canonical learning and scenario metadata.
- Advance the canonical `audience-scope-discipline` package metadata to 1.0.1 while Arcantry remains at 1.0.0.

# Out of scope

- Changing Arcantry's product or CLI version from 1.0.0.
- Changing the skill's invocation policy or provider metadata.
- Replacing the existing decision scenarios or evaluation rubric.
- Creating a release tag, GitHub Release or package publication.
