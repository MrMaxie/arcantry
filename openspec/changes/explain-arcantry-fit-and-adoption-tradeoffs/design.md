# Approach

Build one progressive evaluation path. Begin with verified problems and observable outcomes, follow with representative before-and-after project examples, then expose the Arcantry source model and technical contracts. Provide separate decision guidance for an individual developer and a team evaluator without duplicating the same product claims.

Describe adjacent practices by semantic ownership: ADRs and RFCs retain decision rationale and alternatives, issue trackers retain delivery coordination, project documentation retains durable usage knowledge, and release systems retain delivery history. Arcantry explains how its supported sources connect those roles and where an already disciplined repository may not benefit enough to justify adoption.

# Trade-offs

Decision-oriented guidance adds maintenance obligations because cost and capability claims must stay aligned with executable product behavior. Bounded representative scenarios are preferred over broad benchmarks or return estimates that the repository cannot verify.
